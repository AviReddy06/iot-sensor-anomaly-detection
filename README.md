## 1. System Overview

This project provides an end-to-end full-stack anomaly detection system for indoor climate telemetry. It separates customer presentation from administrative engineering:
- **Client Route (`/`)**: A digital thermohygrograph interface designed specifically for room occupants and facility managers. Displays a dual-trace continuous strip chart (`#9B2C2C` temperature, `#1D5C8C` relative humidity) on archival ruling paper (`#EEF1EF`), a 2D temperature-humidity phase-space map ("Where the room has been"), and a plain-English log of unusual readings with zero ML jargon.
- **Admin Route (`/admin`)**: An authenticated diagnostic cockpit protected by constant-time password verification and signed expiring session tokens. Provides serial device management, simulation replay, transparent model diagnostics, and verified metric audits.
- **Detection Architecture**: Combines a 12-feature session-aware Isolation Forest (200 trees, 3-of-5 persistence gating) with an Adaptive Cauchy EWMA-Z residual detector (`halflife = 2400s`, causal rate-gating to prevent post-event baseline corruption).

## 4. Key Audit Findings & Disclosures

1. **Post-Hoc Pilot Relabelling**: In commit `4f8ca08`, the pilot event annotations were expanded from 46 rows to 504 rows after inspecting detector predictions. Under the original 46-row labels, Isolation Forest produced 280 false positives (F1 = 0.247); under the revised labels, those same detections are counted as true positives, yielding F1 = 0.932. Consequently, the pilot dataset functions as **development tuning data**, not independent held-out evaluation.

2. **Synthetic Evaluation Suite**: The 143 anomalous rows in `eval_test_suite.csv` are synthetic injections (seed 42) into clean held-out DHT11 telemetry across six fault types. These are **never mixed** with recorded-event results in reporting.

3. **IoTsec False Alarms (470 FP)**: On the external IoTsec benchmark, the hybrid detector achieved 99.4% recall but generated 470 false alarms (Precision = 0.509). This demonstrates that applying the detector across different physical rooms without site-specific baseline recalibration triggers frequent false alarms due to baseline temperature and humidity shifts.

4. **Test and Pilot Dataset Overlap**: `data/raw/test.csv` (55 rows) and `data/raw/pilot_data.csv` share **35 identical rows** between 22:02:14 and 22:03:23 on 2026-10-27 before the test event occurs. The pilot has no rows for 22:03:25–22:04:05 where the test event is located.

5. **Threshold Tuning**: The 0.25th percentile threshold (-0.21657) in earlier experimental settings was chosen via grid optimization against the synthetic evaluation suite (Development data). The production web application uses calibrated percentiles: Low (0.5%), Medium (1.0%, default), and High (5.0%).

6. **False Alarm Qualification**: Claims of "zero false alarms" apply strictly to the specific 57-row live holdout session (`live_baseline_2026-11-10.csv`) and the revised pilot baseline; they do **not** generalize to arbitrary uncalibrated external environments.

## 5. System Limitations & Boundaries

- **Sampling Cadence Limit**: The DHT11 sensor requires a minimum 2.0-second recovery interval (0.5 Hz). Transient electrical or thermal phenomena lasting under 2 seconds cannot be detected.
- **Hardware Quantization**: Although firmware prints readings formatted to one decimal place (`0.1`), the DHT11 physical sensing element has an internal precision of ±1.0°C and ±5.0% RH. **UNKNOWN**: Whether the sensor is actually a DHT22 (label not verified).
- **Cross-Domain Transfer**: The detector cannot be transferred across rooms with differing ambient HVAC dynamics without recalibrating baseline parameters (IoTsec: 470 FP, Precision 0.509).
- **Supervision Nature**: The system operates in an unsupervised manner on normal environmental telemetry; anomalies are defined statistically and physically relative to recent baseline behavior rather than explicit fault classification.
- **No Hardware Validation**: No ESP32 board was connected during evaluation; all tests used simulated data replay.
- **Event Production Method Unknown**: How the test event, two pilot events, and blowing episodes in normal data were produced is **UNKNOWN** (ask student).
- **Load/Soak/CI Testing Not Performed**: No load tests, CI pipeline, or soak tests were executed.

## 8. Security Posture

- **Authentication**: Signed HMAC-SHA256 tokens (8h expiry), constant-time comparison, rate limiting (5 failures/min → 429)
- **Admin Protection**: Routes return 503 if `ADMIN_PASSWORD` unset; WebSocket rejects with code 1008
- **Upload Security**: 5MB limit, CSV header validation, server-generated filenames, path traversal blocked (plain & encoded)
- **CSV Export Safety**: Formula injection protection (`=`, `+`, `-`, `@` prefixed with apostrophe)
- **Security Headers**: CSP (`default-src 'self'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`
- **No Secrets in Tracked Files**: Verified by automated scan
